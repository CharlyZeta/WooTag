# CONTRACT: El botón "Generar QR de PC" no abre nada (modo Companion inalcanzable)
# ID: FIX-0012
# Status: DRAFT
# Mode: GATE
# Gate-Mode: STRICT

## Intent
El modo Companion (vincular un celular invitado por QR) está ofrecido en la UI pero es imposible de usar. Los botones que lo abren se muestran solo cuando **no** hay cuenta cloud, mientras que `<HostRoomModal>` se monta solo cuando **sí** hay cuenta cloud. Además no existe autenticación anónima. El botón queda muerto en el caso de invitado y desaparece en el caso de usuario logueado.

## Reproduction Steps
1. Sin iniciar sesión en la nube, conectar una tienda WooCommerce en escritorio (viewport ≥ 768 px).
2. Ir a la pestaña **Importar → Escáner & Móvil**.
3. Pulsar **"Generar QR de PC"** (o el ícono de celular del header).
4. Observar que no se abre ningún modal y que `isHostModalOpen` queda en `true` sin efecto.
5. Repetir con sesión cloud iniciada: los botones ya no se muestran.

## Current Behavior
- `components/controls/ImportTab.tsx`: bloque host visible solo si `!isMobile && !currentUser && !activeRoomId`.
- `components/Controls.tsx`: `<HostRoomModal>` renderizado solo si `wooConfig && currentUser`.
- `contexts/AuthContext.tsx`: no hay `signInAnonymously` en ningún punto del proyecto.
- El ícono del header (`Controls.tsx`) además usa `disabled={activeRoomId !== null && isHostModalOpen === false}`, lógica sin sentido funcional.

## Expected Behavior
Definir un único camino coherente: o bien un invitado puede crear la sala y vincular su celular (auth anónima + reglas de Firestore acotadas a `rooms/{roomId}`), o bien el flujo se elimina y se exige cuenta cloud, dejando la UI sin botones muertos. En ambos casos, crear sala → mostrar QR → el móvil se une → los productos escaneados aparecen en la PC.

## Business Rules
- BR-001: La UI no debe ofrecer una acción que no puede ejecutarse con el estado actual de sesión.
- BR-002: Si se habilita para invitados, la sala debe crearse con un ID criptográfico (ya implementado en `createRoom`) y las reglas de Firestore deben limitar el acceso a esa sala.
- BR-003: El flujo con cuenta cloud debe seguir funcionando sin cambios de UX.

## Acceptance Criteria
- AC-001: GIVEN un usuario sin cuenta cloud, en escritorio y con WooCommerce conectado WHEN pulsa "Generar QR de PC" THEN se muestra un QR de sala y el documento `rooms/{roomId}` existe en Firestore.
- AC-002: GIVEN esa sala activa WHEN un móvil escanea el QR y se une THEN la PC recibe `guestJoined` y los productos escaneados en el móvil aparecen en la hoja.
- AC-003: GIVEN cualquier combinación de sesión/viewport WHEN recorro la UI THEN ningún botón de vinculación queda visible sin acción disponible.
