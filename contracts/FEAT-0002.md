# CONTRACT: Modo Operador Móvil / Góndola (Escaneo Continuo, Feedback Háptico/Sonoro, Auditoría de Precios y Optimizador A4)
# ID: FEAT-0002
# Status: RESOLVED
# Mode: LOOP
# Gate-Mode: STRICT

## Intent
Crear una interfaz móvil exclusiva y optimizada (Modo Operador / Góndola) accesible mediante una URL dedicada (`#/mobile` o `?mode=mobile`), eliminando la previsualización pesada de hojas A4 en dispositivos móviles, proporcionando escaneo ágil con feedback háptico y sonoro tenue, integración en tiempo real con la auditoría de precios de FEAT-0001 para comparar precios en góndola, y un optimizador visual que calcule cuántas etiquetas van cargadas contra cuántas faltan para completar hojas A4 completas según la grilla configurada, manteniendo intacta la interfaz de escritorio/tablet.

## Use Case
**Actor:** Operador de tienda o repositor de góndola utilizando un teléfono móvil o dispositivo de mano.
**Goal:** Recorrer las góndolas escaneando productos rápidamente para validar precios contra WooCommerce/Snapshot, recibir confirmación sensorial (vibración y sonido sutil), agregar etiquetas a imprimir optimizando el aprovechamiento de hojas A4, y sincronizar la cola de impresión automáticamente con la PC/servidor.

### Main Flow
1. El operador ingresa a la aplicación desde su móvil navegando a `#/mobile` o seleccionando el acceso directo "Modo Móvil / Góndola" desde la barra superior.
2. La vista móvil carga una interfaz limpia y ligera sin el renderizado del lienzo A4 ni barras laterales complejas:
   - Encabezado con estado de tienda activa, conexión Cloud y botón para alternar a la vista clásica completa (PC/Tablet).
   - **Tarjeta Optimizadora de Hojas A4**: Muestra el total de etiquetas agregadas ($N$), capacidad por hoja ($C = \text{cols} \times \text{rows}$), hojas completadas ($\lfloor N / C \rfloor$), etiquetas faltantes para completar la hoja actual ($(C - (N \pmod C)) \pmod C$), y barra de progreso porcentual.
3. El operador utiliza el escáner de cámara integrado (o el campo de ingreso rápido de código de barras/SKU) para leer una etiqueta de góndola.
4. Al detectar el producto:
   - Si está conectado a WooCommerce y con snapshot de precios activo (`FEAT-0001`), compara el precio del producto en catálogo contra el snapshot guardado:
     - Si hay disparidad de precio, destaca visualmente: *"Diferencia detectada: Antes $X.XX → Ahora $Y.YY"*.
     - Si es un producto nuevo sin precio previo: *"Producto nuevo / sin etiqueta previa"*.
     - Si coincide: *"Precio al día"*.
   - Se agrega el producto a la cola de etiquetas a imprimir.
   - **Feedback sensorial inmediato**:
     - Vibración háptica tenue (`navigator.vibrate([40])`).
     - Tono sonoro sutil y breve mediante Web Audio API (frecuencia dulce de 587Hz con decaimiento exponencial suave de 60ms a volumen bajo) que no satura ni requiere descargas de archivos de audio externos.
5. El optimizador de hoja A4 actualiza en tiempo real el contador y la barra de progreso.
6. La lista de etiquetas se sincroniza automáticamente con el perfil de Firebase / Firestore del usuario para que esté lista para imprimir en la computadora principal.
7. El operador puede revisar la lista agregada, eliminar ítems, ajustar cantidades o presionar "Imprimir / Enviar" según corresponda.

### Alternative Flows
- **AF-1 (Navegación entre modos):** El usuario puede conmutar en cualquier momento entre el "Modo Góndola Móvil" y la "Vista Completa (PC / Tablet)" con un botón visible en ambas vistas sin perder los productos cargados ni la sesión.
- **AF-2 (Sin vibración o audio disponible):** Si el navegador móvil no soporta `navigator.vibrate` o el audio context está bloqueado por el sistema operativo, la confirmación visual en pantalla se ejecuta sin provocar errores en la aplicación.
- **AF-3 (Producto no encontrado por SKU/Código):** Si el código escaneado no coincide con ningún producto en la tienda, emite un aviso visual claro ("SKU no encontrado en catálogo") y no altera el contador de hojas A4.
- **AF-4 (Modo offline / sin conexión Woo):** Si no hay tienda conectada, la vista móvil permite ingresar productos manualmente o muestra el selector de conexión rápida.

## Business Rules
- **BR-001 (URL y Preservación de Vista de Escritorio):** La URL dedicada móvil se resolverá mediante hash routing `#/mobile` o query param `?mode=mobile`. La experiencia actual de escritorio y tablets con previsualización A4 no debe modificarse ni degradarse.
- **BR-002 (Feedback Sensorial No Invasivo):** El feedback sonoro debe implementarse con Web Audio API sintetizado puro (sin archivos MP3 externos) a un volumen moderado/bajo (< 10% ganancia) con envolvente corta (< 80ms) y vibración corta (<= 40ms) para garantizar velocidad y cero dependencia de red.
- **BR-003 (Cálculo del Optimizador A4):** La capacidad de etiquetas por hoja se calcula dinámicamente como $\text{capacidad} = \text{layoutCols} \times \text{layoutRows}$ a partir de la configuración activa.
  - Si $N = 0$: 0 etiquetas, faltan $C$ para 1 hoja.
  - Si $N > 0$ y $N \pmod C == 0$: hojas completas $= N / C$, 0 faltantes para la hoja cerrada (hoja 100% optimizada).
  - Si $N \pmod C \neq 0$: faltan $C - (N \pmod C)$ etiquetas para completar la hoja actual.
- **BR-004 (Integración con FEAT-0001):** La vista móvil consumirá los datos del snapshot de `priceSnapshotService` y la lista de `pricePendings` para señalar al operador si la etiqueta escaneada requiere cambio de precio o si está actualizada.
- **BR-005 (Sincronización en Tiempo Real):** Todo producto agregado o eliminado desde la vista móvil se reflejará inmediatamente en la sesión global (`products`) y en Firestore/Cloud Profile para permitir impresión remota desde la terminal de PC.

## Acceptance Criteria
- **AC-001:** GIVEN la aplicación cargada WHEN la URL contiene `#/mobile` o `?mode=mobile` THEN se renderiza la vista exclusiva `MobileScannerView` en lugar del diseño estándar de escritorio con hojas A4.
- **AC-002:** GIVEN un botón de conmutación en la barra superior WHEN el usuario hace clic THEN alterna entre la vista móvil y la vista de escritorio preservando el estado de productos y configuración.
- **AC-003:** GIVEN la vista móvil activa WHEN se agrega o escanea exitosamente un producto THEN se ejecuta `navigator.vibrate` y se reproduce un tono Web Audio sutil de confirmación.
- **AC-004:** GIVEN una grilla con $C = 24$ etiquetas por página y $14$ productos cargados WHEN se visualiza el optimizador A4 THEN informa "14 cargadas", "Faltan 10 para completar la hoja", y barra de progreso al $58.3\%$.
- **AC-005:** GIVEN una grilla con $C = 24$ y $24$ productos cargados WHEN se visualiza el optimizador A4 THEN informa "1 hoja completa (24 etiquetas)", "Hoja completa (0 sobrantes)", y progreso al $100\%$.
- **AC-006:** GIVEN un producto escaneado con precio diferente al registrado en el snapshot de FEAT-0001 WHEN se presenta en la vista móvil THEN se muestra una alerta indicando la diferencia de precio (Antes vs Ahora).
- **AC-007:** GIVEN un dispositivo sin soporte para `vibrate` o con audio suspendido WHEN se agrega un producto THEN no se lanzan excepciones no capturadas y el flujo visual continúa con normalidad.
