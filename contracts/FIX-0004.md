# CONTRACT: Credenciales de WooCommerce en la query string y sin exigir HTTPS
# ID: FIX-0004
# Status: RESOLVED
# Mode: LOOP
# Gate-Mode: EXPRESS

## Intent
`makeWooRequest` reintenta con `consumer_key` y `consumer_secret` en la URL cuando el primer intento devuelve 401 o 403, y ninguna capa valida que la URL de la tienda use HTTPS. En la query string las credenciales quedan en logs de acceso del servidor, historiales y proxies; sobre `http://` viajan en claro.

## Reproduction Steps
1. Configurar una tienda con `url: "http://tienda.example.com"` y mockear `fetch` para que el primer intento responda 401.
2. Llamar `fetchProductBySku("ABC", config)`.
3. Inspeccionar las llamadas a `fetch`: la primera usa `Authorization: Basic` sobre `http://`, y la segunda lleva `consumer_key=...&consumer_secret=...` en la URL.

## Current Behavior
`services/wooService.ts` (líneas 30-34): ante 401/403 repite la petición con las credenciales en la URL, sin condiciones. No encontré validación de esquema en `wooService.ts` ni en `ConnectionModal.tsx` (búsqueda por patrón), de modo que `http://` se acepta. No hay comentario en el código ni entrada de `changelog.txt` que explique por qué existe el fallback. El comportamiento actual está fijado por dos tests en `services/wooService.test.ts` (líneas 124-143).

## Expected Behavior
Las credenciales solo se envían a URLs `https:` (con excepción de desarrollo local en `localhost` y `127.0.0.1`). Si la URL no es segura, las funciones de servicio rechazan la llamada sin ejecutar ninguna petición `fetch`.

## Business Rules
- BR-001: `makeWooRequest` no debe enviar credenciales a una URL cuyo esquema no sea `https:`, salvo hosts `localhost` y `127.0.0.1`.

## Acceptance Criteria
- AC-001: GIVEN una config con `url: "http://tienda.example.com"` WHEN se llama `validateConnection` THEN se rechaza con un error que indica que se requiere HTTPS y `fetch` no es invocado.
<!-- Este AC debe FALLAR hoy y PASAR después del fix -->
- AC-002: GIVEN la misma config `http://` WHEN se llama `fetchProductBySku`, `fetchProductsByName`, `fetchProductsByCategory` o `fetchCategories` THEN cada promesa se rechaza con el mismo error y `fetch` no es invocado.
- AC-003: GIVEN una config con `url: "http://localhost:8080"` WHEN se llama `validateConnection` THEN `fetch` se invoca normalmente, sin error de esquema.
