# CONTRACT: El snapshot de precios no se actualiza al imprimir (IDs de producto convertidos a NaN)
# ID: FIX-0011
# Status: RESOLVED
# Mode: LOOP
# Gate-Mode: STRICT

## Intent
FEAT-0001 (AC-005) define que al imprimir etiquetas se actualiza el snapshot de precios en Firestore y los pendientes impresos desaparecen. Hoy eso no ocurre: `Product.id` es un ID de instancia (`"123-1729000000000-abc"`) y `Number(p.id)` da `NaN`, que `updateProductsInSnapshot` descarta en silencio. El snapshot nunca se actualiza y el pendiente reaparece en cada carga.

La suite no lo detecta porque `priceSnapshotService.test.ts` (AC-005) invoca el servicio con `id: 50` numérico, un formato que **nunca** llega desde la app: todos los caminos de alta (WooCommerce, árbol de categorías, XLS, escáner) reescriben el ID con sufijos. El test valida el servicio en un escenario que no existe en producción.

## Reproduction Steps
1. Iniciar sesión en la nube y conectar un sitio WooCommerce (esto crea el baseline en `users/{uid}/snapshots/{siteId}`).
2. Cambiar el precio de un producto en WooCommerce y recargar la app: el producto aparece como pendiente (`PRICE_CHANGED`).
3. Abrir la auditoría, agregar ese producto a la hoja e imprimir.
4. Revisar en Firestore el documento del snapshot y volver a abrir la auditoría: el precio guardado no cambió y el producto sigue pendiente.

## Current Behavior
- `App.tsx` (`handlePrint`) arma `printedIds` con `Number(p.id)` y llama a `updateProductsInSnapshot` pasando `id: p.id` (string con sufijo).
- `services/priceSnapshotService.ts` (`updateProductsInSnapshot`) hace `const numId = Number(p.id)` y, si `isNaN(numId)`, **omite la entrada sin error**.
- `App.tsx` (`handleAddProduct`), `components/controls/ImportTab.tsx` (árbol y XLS) y `services/cloudProfiles.ts` (`addProductToCloudProfile`) agregan sufijos al ID en tres capas distintas.
- `services/wooService.ts` (`mapWooProduct`) tiene disponible el ID numérico de WooCommerce y lo descarta al crear el `Product`.
- Resultado: `users/{uid}/snapshots/{siteId}.entries` queda intacto y `setPricePendings` filtra contra un `Set` de `NaN` (no-op).

## Expected Behavior
Al imprimir, los productos con origen WooCommerce actualizan su entrada del snapshot por su ID numérico y desaparecen de pendientes. Los productos sin origen numérico (XLS, manuales) no rompen nada, no escriben `NaN` y dejan rastro observable de cuántos se omitieron. El formato del snapshot no cambia: FEAT-0001 sigue vigente sin modificaciones.

## Entities Affected
- `types.ts` — `Product` (nuevo campo `sourceId?: number`).
- `services/wooService.ts` — `mapWooProduct` / `fetchAllCatalogProducts` (poblar `sourceId`).
- `services/priceSnapshotService.ts` — `updateProductsInSnapshot` (resolver ID, devolver contadores).
- `App.tsx` — `handlePrint` (usar `sourceId` para snapshot y limpieza de pendientes).
- `services/priceSnapshotService.test.ts` — corregir AC-005 (usaba IDs numéricos irreales) y agregar los casos nuevos.

## Business Rules
- BR-001: El ID numérico de WooCommerce se conserva en `Product.sourceId?: number`, separado del ID de instancia que usa React. Se puebla en el mapeo de WooCommerce; los productos de XLS o manuales lo dejan `undefined`.
- BR-002: `updateProductsInSnapshot` nunca escribe entradas con ID no numérico. Las descarta dejando rastro observable: `console.warn` con la cantidad omitida y retorno `{ updated: number; skipped: number }`. No lanza excepción.
- BR-003: Los productos originados en XLS o creados a mano siguen funcionando igual que hoy (sin `sourceId`, no actualizan snapshot, no rompen la impresión).
- BR-004: No se modifica el contrato FEAT-0001: el formato de `PriceSnapshotMap`/`entries` y las reglas de detección (`PRICE_CHANGED` / `NEW_PRODUCT`) quedan intactos.
- BR-005: La limpieza de pendientes posterior a la impresión considera "impreso" únicamente a los productos con `sourceId` numérico; nunca usa `Number(instanceId)`.

## Acceptance Criteria
- AC-001: GIVEN un producto pendiente con `sourceId` 123 WHEN imprimo etiquetas que lo incluyen THEN `snapshots/{siteId}.entries[123].regularPrice` queda con el precio actual y el producto deja de aparecer en pendientes.
- AC-002: GIVEN etiquetas cargadas desde XLS (sin `sourceId`, `id` con formato `xls-…`) WHEN imprimo THEN no se lanza excepción y el snapshot no recibe entradas `NaN`.
- AC-003: GIVEN `updateProductsInSnapshot` WHEN recibe una lista con IDs no numéricos THEN los descarta, devuelve `{ updated: 0, skipped: N }` y emite `console.warn` (hoy: descarte silencioso).
- AC-004: GIVEN un `Product` con `sourceId: 123` e `id: "123-1729000000000-abc"` WHEN llamo `updateProductsInSnapshot` THEN escribe `entries[123]` con el precio indicado y devuelve `{ updated: 1, skipped: 0 }`.
- AC-005: GIVEN una hoja mixta (un producto Woo con `sourceId` y uno XLS sin él) WHEN imprimo THEN solo se actualiza la entrada del producto Woo y el pendiente de ese producto desaparece, sin tocar el de XLS.
- AC-006: GIVEN el código de impresión WHEN se calcula el conjunto de productos "impresos" para limpiar pendientes THEN contiene solo `sourceId` numéricos (ningún `NaN`).
