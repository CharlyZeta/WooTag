# CONTRACT: El service worker no cachea nada y se sirve con cache inmutable de un año
# ID: FIX-0028
# Status: RESOLVED
# Mode: GATE
# Gate-Mode: EXPRESS

## Intent
La app registra un service worker (`public/sw.js`, 236 bytes) que no intercepta ni cachea nada: la PWA es instalable pero no funciona offline. Peor: `.htaccess` aplica `immutable, max-age=31536000` a todo `.js`, incluido `sw.js`, así que el navegador puede quedarse hasta un año con un service worker viejo y sin forma de actualizarlo. Se ofrece instalación PWA sin cumplir la promesa.

## Reproduction Steps
1. Abrir `public/sw.js`: handlers `install` (skipWaiting) y `fetch` vacío, sin `Cache API`.
2. Instalar la PWA desde el navegador y cortar la red.
3. Recargar: la app no carga (no hay precache del shell).
4. Revisar `public/.htaccess`: `FilesMatch "\.(js|css|...)$"` con `Cache-Control: public, max-age=31536000, immutable`, aplicable a `sw.js`.

## Current Behavior
- El service worker se registra en `index.html` pero no tiene estrategia de caché ni versionado.
- No hay `manifest` de precache, ni actualización controlada, ni aviso de "nueva versión disponible".
- `sw.js` cae en la regla de cache inmutable de un año.
- El roadmap del README lista "PWA / instalable como app de escritorio" como pendiente, aunque ya hay registro y manifest.

## Expected Behavior
Una decisión explícita y coherente:
- **Opción A (PWA real):** precache del shell + assets hasheados, versionado por build, `skipWaiting` controlado, aviso de actualización y exclusión de `sw.js` del cache inmutable.
- **Opción B (sin PWA):** se elimina el registro y el manifest, y no se ofrece instalación.

En cualquiera de las dos, `sw.js` nunca se sirve como inmutable.

## Business Rules
- BR-001: `sw.js` se sirve con `Cache-Control: no-cache` (o `max-age` muy corto) para permitir actualizaciones.
- BR-002: No se muestra la instalación PWA si no hay soporte offline real (o se implementa).
- BR-003: Un deploy nuevo debe llegar a los clientes existentes sin intervención manual.
- BR-004: La estrategia de caché no rompe el flujo de impresión ni la carga de assets hasheados.

## Acceptance Criteria
- AC-001: GIVEN un cliente con el SW de la versión anterior WHEN se publica un deploy nuevo y recarga THEN recibe la versión nueva (verificado por cambio de versión visible en el header).
- AC-002: GIVEN `sw.js` WHEN se sirve desde el hosting THEN la respuesta no tiene `immutable` ni `max-age` de un año.
- AC-003: GIVEN la opción elegida WHEN abro la app sin red THEN el service worker no cachea nada y la documentación aclara que la app es instalable pero **no** funciona offline.
