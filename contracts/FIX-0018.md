# CONTRACT: La optimización con Gemini no se puede configurar (BYOK sin interfaz)
# ID: FIX-0018
# Status: RESOLVED

# Gate-Mode: EXPRESS

## Intent
FIX-0001 sacó la API key del bundle y adoptó "Bring Your Own Key" leyendo `localStorage['gemini_api_key']`. Pero **ninguna pantalla escribe esa clave**: el usuario final no tiene forma de habilitar la IA y el botón ✨ devuelve la descripción original en silencio, así que la feature parece rota. Hoy sólo se activa abriendo DevTools.

Decisión de Gate (2026-10-20): la clave se configura desde **Ajustes → "Optimización con IA"**, que abre un **modal** para pegarla, con un botón **"Probar API Key"** que hace una consulta genérica interna y exige un resultado aceptable antes de permitir guardar.

## Reproduction Steps
1. Abrir la app sin key configurada y cargar un producto con descripción larga.
2. Ir a **Lista** y pulsar ✨: la descripción no cambia y no hay aviso.
3. Ir a **Ajustes** y buscar dónde configurar la IA: no existe ningún control.
4. Inspeccionar `localStorage`: `gemini_api_key` no existe.

## Current Behavior
- `services/geminiService.ts`: `getApiKey()` lee `localStorage['gemini_api_key']` y cae a `process.env.API_KEY` (vacío en build). `optimizeDescription` captura el error, hace `console.error` y **devuelve la descripción original** (`Promise<string>`), sin señal para la UI.
- `App.handleOptimizeDescription` sólo loguea en `catch`: nunca muestra nada.
- `components/controls/LayoutTab.tsx` no tiene ninguna sección de IA.
- No hay forma de probar una clave antes de usarla.

## Expected Behavior
- **Ajustes** muestra una sección "Optimización con IA (Gemini)" con el estado actual ("IA habilitada" / "IA deshabilitada"), un indicio enmascarado de la clave cuando existe, y el botón **"Configurar IA"** que abre un modal.
- El **modal** tiene: campo `type="password"`, botón **"Probar API Key"** (consulta genérica: pide una respuesta trivial y valida que llegue un resultado aceptable), botón **"Guardar clave"** habilitado sólo si la prueba fue exitosa en esta sesión (o si la clave ya estaba guardada), y **"Eliminar clave"** cuando hay una.
- La clave se guarda **sólo en este navegador** (`localStorage`); nunca se sincroniza a Firestore ni se embebe en el bundle.
- Sin clave, la optimización no es silenciosa: la UI avisa y la descripción original queda intacta.
- Con clave válida, ✨ reemplaza la descripción por la versión optimizada (≤ 15 palabras).
- Ante cuota agotada, red caída o clave inválida, la UI muestra el motivo y la descripción original se conserva.
- Se mantiene FIX-0001 AC-002: `optimizeDescription` **no lanza excepciones**.

## Entities Affected
- `utils/aiKeyStorage.ts` — **nuevo** (puro, sin SDK): `AI_KEY_STORAGE_KEY`, `getAiKey`, `setAiKey`, `clearAiKey`, `hasAiKey`.
- `services/geminiService.ts` — usa la utilidad; `optimizeDescription` devuelve resultado tipado; nuevo `testGeminiApiKey(apiKey)` con consulta genérica y validación de respuesta aceptable.
- `components/AiKeyModal.tsx` — **nuevo**: pegar clave, probar, guardar, eliminar.
- `components/controls/LayoutTab.tsx` — sección de estado + botón que abre el modal.
- `App.tsx` — `handleOptimizeDescription` muestra el aviso y sólo reemplaza la descripción si la optimización fue exitosa.
- `services/geminiService.test.ts` — adaptar aserciones al resultado tipado (sin debilitar la intención de FIX-0001).

## Business Rules
- BR-001: La clave se guarda por dispositivo en `localStorage['gemini_api_key']`; nunca en Firestore, en el bundle ni en logs.
- BR-002: Sin clave, la optimización falla de forma observable (aviso visible) y conserva la descripción original.
- BR-003: `optimizeDescription` no lanza: devuelve `{ ok: false, description: <original>, error: <motivo> }` cuando no puede optimizar (preserva FIX-0001 AC-002).
- BR-004: El campo de clave es `type="password"`; la UI nunca muestra la clave completa, sólo un indicio enmascarado (por ejemplo `AIza…7f3c`).
- BR-005: "Probar API Key" hace una consulta **genérica e interna** (un prompt trivial) y considera éxito sólo si la respuesta es no vacía y coherente con lo pedido; distingue clave inválida, cuota agotada y error de red en el mensaje.
- BR-006: No se persiste una clave que no haya pasado la prueba en la sesión actual (evita guardar claves inválidas), salvo que sea la clave ya almacenada.
- BR-007: "Eliminar clave" la borra de `localStorage`, vuelve el estado "IA deshabilitada" y no toca nada más.
- BR-008: `vite.config.ts` sigue definiendo `process.env.API_KEY`/`GEMINI_API_KEY` como vacío: la clave nunca viaja en el build.

## Acceptance Criteria
- AC-001: GIVEN la app sin clave WHEN abro **Ajustes** THEN veo la sección "Optimización con IA" con estado "IA deshabilitada" y un botón "Configurar IA" que abre el modal con un campo `type="password"`.
- AC-002: GIVEN el modal abierto WHEN ingreso una clave válida y pulso "Probar API Key" THEN se muestra el éxito y se habilita "Guardar clave" (con la API mockeada).
- AC-003: GIVEN el modal abierto WHEN ingreso una clave inválida y pulso "Probar API Key" THEN se muestra el motivo del fallo y "Guardar clave" permanece deshabilitado.
- AC-004: GIVEN una prueba exitosa WHEN guardo THEN la clave queda en `localStorage`, el estado pasa a "IA habilitada" y `optimizeDescription` la usa (mock: `ok: true` con descripción optimizada).
- AC-005: GIVEN una clave guardada WHEN pulso "Eliminar clave" THEN `localStorage` deja de tenerla y el estado vuelve a "IA deshabilitada".
- AC-006: GIVEN una clave inválida o cuota agotada al usar ✨ WHEN optimizo THEN la descripción original se conserva, `optimizeDescription` devuelve `ok: false` sin lanzar y la UI muestra el aviso.
- AC-007: GIVEN una clave guardada WHEN imprimo, sincronizo y navego THEN la clave no aparece en ningún payload de Firestore ni en el bundle de producción.
