## Intent
FIX-0001 sacó la API key del bundle y adoptó "Bring Your Own Key" leyendo `localStorage['gemini_api_key']`. Pero **ninguna pantalla escribe esa clave**: el usuario final no tiene forma de habilitar la IA, y el botón ✨ devuelve silenciosamente la descripción original. La feature queda muerta y el silencio la vuelve indistinguible de un fallo.

## Reproduction Steps
1. Abrir la app recién instalada (sin key configurada) y cargar un producto con descripción larga.
2. Ir a la pestaña **Lista** y pulsar el botón ✨ del producto.
3. Observar que la descripción no cambia y que no hay mensaje de error ni aviso.
4. Inspeccionar `localStorage`: `gemini_api_key` no existe y no hay ningún control en la UI que lo escriba.

## Current Behavior
- `services/geminiService.ts` (`getApiKey`) lee `window.localStorage.getItem('gemini_api_key')` y, si no hay, `process.env.API_KEY`, que `vite.config.ts` define como cadena vacía.
- No existe input, modal ni sección de ajustes que guarde esa clave (verificado por búsqueda en todo el código).
- `optimizeDescription` captura el error y devuelve la descripción original sin notificar a la UI.

## Expected Behavior
El usuario puede configurar su API key desde la interfaz (y borrarla), ve el estado de la IA (habilitada/deshabilitada), y cuando la optimización falla o no hay key recibe un aviso visible en lugar de un no-op silencioso.

## Business Rules
- BR-001: La clave nunca se incluye en el bundle de build (`vite.config.ts` sigue definiendo vacío).
- BR-002: La clave se guarda solo en el navegador del usuario y se puede eliminar desde la UI.
- BR-003: Sin key, la IA se muestra como deshabilitada y la app funciona igual que hoy (fallback a la descripción original).
- BR-004: Un fallo de cuota/red se muestra al usuario y no se pierde la descripción original.

## Acceptance Criteria
- AC-001: GIVEN la app sin key WHEN abro la pestaña Ajustes THEN existe un control para pegar la API key y un estado visible "IA deshabilitada".
- AC-002: GIVEN pego una key válida y guardo WHEN pulso ✨ THEN la clave se persiste en `localStorage` y la descripción se reemplaza por la versión optimizada (con la API mockeada en test).
- AC-003: GIVEN una key inválida o cuota agotada WHEN optimizo THEN veo un aviso de error y la descripción original se conserva.
