# CONTRACT: El dev server se cae con EBUSY al vigilar archivos bloqueados (capturas)
# ID: FIX-0030
# Status: RESOLVED

## Intent
Al entrar al modo operador móvil, la app "se cerró" y la consola mostró:

```
Error: EBUSY: resource busy or locked, watch 'D:\ProyectosDual\WooTag\WooTag\screenshots\1.png'
  at FSWatcher.<computed> (node:internal/fs/watchers:321:19)
  ...
Emitted 'error' event on FSWatcher instance
```

No es un bug de la aplicación: es el **file watcher de Vite** intentando vigilar un PNG de `screenshots/` que otro proceso (la herramienta de capturas) tenía bloqueado. En Windows `fs.watch` devuelve `EBUSY` y Vite 6 emite el error como fatal, así que el proceso de desarrollo muere y la página queda sin servidor. Coincidió con el click en "cambiar a operador móvil" porque en ese momento se estaba escribiendo la captura.

## Reproduction Steps
1. `npm run dev` (Vite en `http://localhost:3000`).
2. Guardar o mover una imagen en `screenshots/` mientras otro proceso la mantiene abierta (por ejemplo, tomar una captura con una herramienta que escribe el PNG).
3. Vite intenta agregarla al watcher y recibe `EBUSY`.
4. El dev server se cae; recargar la página no responde.

## Current Behavior
- `vite.config.ts` no define `server.watch.ignored`.
- Vite vigila **todo el proyecto**, incluidos `screenshots/`, `dist/`, `coverage/`, `graphify-out/`, `.sdd/` y `.git/`.
- Cualquier archivo bloqueado en esos directorios puede tumbar el servidor de desarrollo.
- Estado real de la app verificado con capturas: el modo móvil (`#/mobile`) renderiza bien (optimizador A4, cámara pausada, auto-agregar) — el fallo era del entorno, no del código.

## Expected Behavior
- El watcher ignora todo lo que no es código fuente: `screenshots/`, `dist/`, `coverage/`, `graphify-out/`, `.sdd/`, `.git/` y `node_modules/`.
- Tomar capturas, reconstruir o actualizar el grafo ya no puede tumbar el dev server.
- El puerto (3000) y el host (0.0.0.0) de desarrollo no cambian.
