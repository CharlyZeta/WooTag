# CONTRACT: Dependencias de producción con vulnerabilidades (xlsx y transitivas)
# ID: FIX-0005
# Status: DRAFT
# Mode: GATE
# Gate-Mode: EXPRESS

## Intent
`npm audit --omit=dev` reporta 8 vulnerabilidades en dependencias de producción (2 critical, 5 high, 1 moderate). Siete son transitivas y tienen fix disponible; `xlsx@0.18.5` es directa y no tiene fix publicado en npm (prototype pollution GHSA-4r6h-8v6p-xvw6 y ReDoS GHSA-5pgg-2g8v-p4x9). `xlsx` se incluye en el bundle y parsea archivos que sube el usuario (`utils/xlsImport.ts`).

## Reproduction Steps
1. Ejecutar `npm ci`.
2. Ejecutar `npm audit --omit=dev`.
3. Observar el resumen: 8 vulnerabilidades, con `protobufjs` y `websocket-driver` en critical y `xlsx` en high sin fix.

## Current Behavior
Verificado el 2026-10-10: transitivas (`@grpc/grpc-js`, `@protobufjs/utf8`, `brace-expansion`, `minimatch`, `protobufjs`, `websocket-driver`, `ws`) con `fixAvailable: true`; `xlsx` directa con `fixAvailable: false`. Las transitivas llegan vía Firebase y apuntan a código de Node; su alcance real en el bundle del navegador es probablemente bajo (no verificado). `xlsx` sí se ejecuta en el navegador sobre archivos del usuario. El resumen completo (incluyendo dependencias de desarrollo como `vite <= 6.4.2`) es de 21 vulnerabilidades. El CI no ejecuta `npm audit`.

## Expected Behavior
`npm audit --omit=dev --audit-level=high` termina sin hallazgos y la importación XLS se comporta igual que antes.

## Business Rules
- BR-001: Las dependencias de producción no deben tener vulnerabilidades de severidad `high` o `critical` en `npm audit --omit=dev`.
- BR-002: La importación XLS conserva sus reglas actuales: límite de 5 MB y 500 filas, rechazo de archivos `.xlsm`, sanitización de celdas y validación de URLs de imagen (`utils/xlsImport.ts`).

## Acceptance Criteria
- AC-001: GIVEN el repositorio con las dependencias actualizadas WHEN se ejecuta `npm audit --omit=dev --audit-level=high` THEN el comando termina con exit code 0.

- AC-002: GIVEN la suite existente `utils/xlsImport.test.ts` WHEN se ejecuta tras el cambio THEN todos sus tests pasan sin modificar sus aserciones.
- AC-003: GIVEN el cambio aplicado WHEN se ejecutan `npm test` y `npm run build` THEN pasan los 97 tests y el build termina sin errores.

## Ambiguity Log
- [ ] BR-001 (xlsx): ¿qué mecanismo? Opciones: (A) instalar la versión mantenida de SheetJS publicada en su propio CDN (tarball de cdn.sheetjs.com); según los advisories el fix está en versiones recientes (0.19.3 para prototype pollution y 0.20.2 para ReDoS), pero no pude confirmar la versión vigente ni la compatibilidad exacta de API, hay que verificarlo en el Gate. (B) Reemplazar por otra librería (p. ej. `exceljs` o `read-excel-file`): cambia la API y obliga a reescribir `xlsImport.ts` y sus tests, contradiciendo AC-002. (C) Aceptar el riesgo documentado porque solo se importan archivos propios: BR-001 no se cumpliría.
- [ ] BR-001 (alcance): ¿entran las devDependencies (`vite <= 6.4.2`, 3 high que solo afectan al servidor de desarrollo)? Hoy BR-001 y AC-001 cubren solo producción.
- [ ] Prevención: ¿se agrega `npm audit --omit=dev --audit-level=high` al CI y bloquea el deploy, o solo informa? Un gate bloqueante puede frenar un deploy urgente por un advisory nuevo de terceros.
