# CONTRACT: El deploy no declara en el título qué versión publica
# ID: FIX-0033
# Status: RESOLVED
# Mode: LOOP
# Gate-Mode: EXPRESS

## Intent
El título del run de GitHub Actions es el **asunto del commit**. Varios commits de documentación y capturas no incluían la versión (`docs: add v2.5.20 screenshot gallery…`, `docs(sdd): record…`), así que al mirar el historial de deploys no se puede saber qué versión se publicó en cada uno. Además nada garantizaba que el `dist/` desplegado contuviera la misma versión que declara `package.json`.

## Reproduction Steps
1. Abrir `https://github.com/CharlyZeta/WooTag/actions`.
2. Mirar los títulos de los runs de "Deploy to Production (FTP)".
3. Ver que algunos no dicen ninguna versión (`docs: …`, `docs(sdd): …`).
4. Comparar con `package.json` y con el badge del README: no hay un control automático que los mantenga alineados.

## Current Behavior
- El workflow no valida la versión en ningún punto.
- Los títulos dependen del criterio de quien commitea.
- El build inyecta `__APP_VERSION__` desde `package.json`, pero nadie verifica que el `dist/` publicado la contenga.

## Expected Behavior
- Todo deploy declara la versión que publica en el título del run (asunto del commit).
- El pipeline falla si el asunto no incluye `v<versión de package.json>`.
- El pipeline falla si el README no muestra esa versión o si el bundle no la contiene.
- Los commits de merge no bloquean el deploy.

## Business Rules
- BR-001: El asunto del commit de un push a `main` incluye `vX.Y.Z` igual a `package.json`.
- BR-002: El badge de versión del README coincide con `package.json`.
- BR-003: Después del build, el chunk principal de `dist/assets` contiene la versión inyectada.
- BR-004: Los commits de merge (`Merge …`) quedan exentos del control del título.
- BR-005: El gate no agrega dependencias ni pasos que frenen el desarrollo local (se puede correr con `--subject`).

## Acceptance Criteria
- AC-001: GIVEN el repositorio WHEN ejecuto `npm run verify:version` con un asunto que incluye la versión THEN termina con exit 0 y reporta título, README y (con `--check-dist`) bundle.
- AC-002: GIVEN un asunto sin la versión WHEN ejecuto el script THEN termina con exit 1 y explica el formato esperado.
- AC-003: GIVEN `.github/workflows/deploy.yml` WHEN lo leo THEN el gate corre antes de los tests y `--check-dist` corre después del build y antes del FTP.
- AC-004: GIVEN un commit de merge WHEN corre el gate THEN no falla por el título.

## Ambiguity Log
- [x] **[DEC-2201] ¿Dónde se controla la versión: en el commit, en el run o en el sitio?** — resuelto: **en el commit y en el bundle**. El título del run ya es el asunto del commit, así que controlar el asunto cubre el "título del deploy"; el `--check-dist` cubre el artefacto publicado. Validar el sitio en vivo queda como smoke test manual.
- [x] **[DEC-2202] ¿Bloquear también los commits de documentación?** — resuelto: **sí**, pero con la versión vigente (no es necesario subir versión para un commit de docs, sí declarar qué versión se publica).
