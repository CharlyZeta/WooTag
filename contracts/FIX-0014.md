# CONTRACT: La auditoría de precios descarga el catálogo completo en cada arranque
# ID: FIX-0014
# Status: RESOLVED
# Mode: LOOP
# Gate-Mode: EXPRESS

## Intent
Con cuenta cloud y sitio activo, la auditoría de precios (FEAT-0001) recorre **todas** las páginas del catálogo cada vez que se abre la aplicación. Una tienda de 2.000 productos son 20 requests por carga de página, sin caché ni marca de última auditoría: es la mayor fuente de carga sobre la API de WooCommerce y de latencia de arranque. El efecto automático además no depende de `runPriceAudit` (closure con valores viejos) y se re-dispara con cambios de identidad de `activeSiteId`/`session`.

## Reproduction Steps
1. Iniciar sesión en la nube con un sitio WooCommerce con más de 100 productos publicados.
2. Abrir la app y contar en DevTools los requests a `/wp-json/wc/v3/products?status=publish&per_page=100` (uno por página, hasta `X-WP-TotalPages`).
3. Recargar la app (F5) sin tocar nada.
4. Observar que la descarga completa se repite en cada arranque.

## Current Behavior
- `App.tsx`: `runPriceAudit` hace `Promise.all([loadSnapshot(uid, siteId), fetchAllCatalogProducts(config)])`; el segundo siempre recorre todas las páginas.
- `useEffect` automático con dependencias `[currentUser, activeSiteId, session?.config?.url]`; `runPriceAudit` no figura en las dependencias.
- `services/priceSnapshotService.ts`: `saveSnapshot` escribe `updatedAt` en el documento, pero `loadSnapshot` **descarta** ese campo (devuelve solo `entries`), así que no hay forma de saber si el snapshot está fresco.
- No existe TTL, ni marca de última auditoría, ni camino de "refrescar ahora" separado del arranque.
- `fetchAllCatalogProducts` acepta `onProgress` y nadie lo usa.

## Expected Behavior
- La descarga completa corre como máximo una vez por ventana de frescura (TTL) o cuando el usuario la pide explícitamente desde el modal.
- El resto de las cargas usa el snapshot existente y muestra el estado de la auditoría ("al día hace X min" / "desactualizada").
- Después de cualquier auditoría exitosa se persiste la marca de última auditoría (sin reescribir las entradas del snapshot, porque los pendientes deben seguir visibles hasta imprimirlos o descartarlos).
- El efecto automático deja de re-dispararse por cambios de identidad y respeta el TTL; el botón "Actualizar" del modal siempre fuerza la descarga.
- El baseline inicial y la detección de `PRICE_CHANGED` / `NEW_PRODUCT` no cambian.

## Business Rules
- BR-001: Existe un TTL único y exportado (`PRICE_AUDIT_TTL_MS`) para decidir si una auditoría está fresca.
- BR-002: La decisión "¿corresponde auditar?" vive en una función pura (`shouldRunPriceAudit({ force, lastAuditAt, now, ttlMs })`), testeable sin montar `App`.
- BR-003: Con `force = true` (botón del modal) la descarga completa siempre se ejecuta.
- BR-004: Al completar una auditoría exitosa se persiste `lastAuditAt` sin tocar `entries` (los pendientes no se pierden).
- BR-005: Si la auditoría se saltea por frescura, no se emite ningún request al catálogo ni escritura a Firestore; la UI muestra la frescura en lugar de una lista vacía silenciosa.
- BR-006: El efecto automático depende de `runPriceAudit` (o de refs equivalentes) y no se re-dispara en cada render ni por un `activeSiteId`/`session` reconstruido.
- BR-007: Se mantiene el comportamiento de la línea base inicial y el formato de `PriceSnapshotMap` (FEAT-0001 intacto).

## Acceptance Criteria
- AC-001: GIVEN un snapshot con `lastAuditAt` hace menos del TTL y `force = false` WHEN se evalúa la decisión THEN `shouldRunPriceAudit` devuelve `false` y no se ejecuta `fetchAllCatalogProducts`.
- AC-002: GIVEN el mismo snapshot fresco WHEN el usuario pulsa "Actualizar auditoría" (`force = true`) THEN la descarga completa se ejecuta y se actualiza `lastAuditAt`.
- AC-003: GIVEN un snapshot con `lastAuditAt` más viejo que el TTL WHEN se evalúa la decisión THEN corresponde auditar (`true`).
- AC-004: GIVEN una auditoría exitosa WHEN termina THEN `lastAuditAt` queda persistido en `users/{uid}/snapshots/{siteId}` y `entries` no se modificó (los pendientes siguen pendientes).
- AC-005: GIVEN un snapshot dentro del TTL WHEN se abre la app THEN el modal de auditoría muestra "Auditoría al día" con la antigüedad y un control para forzar la actualización.
- AC-006: GIVEN un día de uso normal WHEN se recarga la app N veces dentro del TTL THEN se ejecuta a lo sumo 1 descarga completa del catálogo (la primera) más las que el usuario fuerce.
