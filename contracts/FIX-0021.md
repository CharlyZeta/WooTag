# CONTRACT: El JSX no está tipado (faltan @types/react y @types/react-dom)
# ID: FIX-0021
# Status: RESOLVED
# Mode: GATE
# Gate-Mode: STRICT

## Intent
FIX-0009 dejó fuera de alcance activar `strict` ("sería un work item aparte"). El problema es mayor: el proyecto **no tiene los tipos de React instalados**. Sin `@types/react`, `JSX.IntrinsicElements` no existe, el JSX se trata como `any` y `noImplicitAny` está apagado, así que `npm run typecheck` valida la lógica TS pero **no las props de ningún componente**. Cualquier prop mal escrita o faltante compila y llega a producción. Medición de esta sesión: `npx tsc --noEmit --strict` da **1.615 errores**, de los cuales **1.319 son TS7026** (JSX implícitamente `any`), 139 TS7006 y 106 TS7031.

## Reproduction Steps
1. Ejecutar `npm ls @types/react @types/react-dom`: salida vacía.
2. Ejecutar `npx tsc --noEmit`: 0 errores (falso verde, porque `strict` está apagado).
3. Ejecutar `npx tsc --noEmit --strict` y contar: 1.615 errores; filtrar `error TS7026`: 1.319.
4. Pasar una prop inválida a `<Controls />` (por ejemplo `onLogoutTypo`) y comprobar que `npm run typecheck` sigue en verde.

## Current Behavior
- `package.json` no declara `@types/react` ni `@types/react-dom`.
- `tsconfig.json` no define `strict`, `noImplicitAny`, `strictNullChecks` ni `noUnusedLocals`; solo `skipLibCheck: true`.
- `npm run typecheck` existe (FIX-0009) y el CI lo ejecuta, pero su señal sobre la capa UI es nula.
- Consecuencia práctica: props como `<Controls>`/`<ImportTab>`/`<Tag>` no están verificadas; `any` explícito aparece 27 veces en el código de app.

## Expected Behavior
Los tipos de React instalados como `devDependencies`, `strict` activo y `npm run typecheck` en verde, con las props de todos los componentes verificadas. El comportamiento en runtime no cambia y los 146 tests siguen pasando sin modificar aserciones.

## Business Rules
- BR-001: `@types/react` y `@types/react-dom` figuran en `devDependencies` y resuelven con `npm ci`.
- BR-002: `strict: true` en `tsconfig.json` (o un plan por etapas aprobado en Gate: primero `strictNullChecks` y `noImplicitAny`, luego el resto).
- BR-003: `npm run typecheck` termina con 0 errores y el CI lo exige antes del build.
- BR-004: No cambia el comportamiento en runtime; los tests existentes pasan sin cambiar aserciones.
- BR-005: Los `any` nuevos quedan prohibidos por lint (ver FIX-0022).
