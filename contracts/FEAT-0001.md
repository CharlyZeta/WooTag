# CONTRACT: Aviso de cambios de precio y SKUs nuevos para reimprimir etiquetas
# ID: FEAT-0001
# Status: RESOLVED
# Mode: LOOP
# Gate-Mode: STRICT

## Intent
Al abrir WooTag con una tienda conectada y sesión iniciada en Firebase, comparar el catálogo publicado completo contra un snapshot de precios guardado en Firestore (`users/{uid}/snapshots/{siteId}`) y avisar qué productos cambiaron de precio o son nuevos/visibles, permitiendo agregarlos a la hoja de impresión para reimprimir etiquetas de exhibición sin revisar el catálogo a mano.

## Use Case
**Actor:** Usuario de WooTag con cuenta Firebase iniciada y una tienda WooCommerce activa.
**Goal:** Detectar automáticamente qué etiquetas de exhibición requieren reimpresión por cambios de precio o nuevos productos, y agregarlas ágilmente a la cola de impresión.

### Main Flow
1. El usuario abre WooTag con sesión de Firebase iniciada y una tienda WooCommerce activa.
2. WooTag lee los productos publicados de la tienda paginando de a 100 con `X-WP-TotalPages`. Se omiten productos ocultos y productos padre variables sin precio determinable (BR-005).
3. WooTag carga de Firestore el snapshot de esa tienda (`users/{uid}/snapshots/{siteId}`). Si no existe snapshot previo (primer arranque), inicializa el baseline con los precios actuales sin marcar pendientes masivos falsos (BR-002).
4. WooTag compara ambos por `productId` (clave inmutable) y genera los pendientes clasificados en:
   - **`PRICE_CHANGED`**: Precio regular o precio de oferta difiere del snapshot guardado.
   - **`NEW_PRODUCT`**: Producto presente en catálogo pero ausente en el snapshot.
5. Si hay pendientes, se muestra un indicador visual destacado (badge/modal) con la cantidad total detectada.
6. El usuario puede seleccionar todos o parte de los productos y agregarlos a la lista de etiquetas.
7. Al imprimir las etiquetas correspondientes, WooTag actualiza el snapshot en Firestore con los precios actuales (BR-003).
8. El usuario también puede descartar un pendiente individualmente o en lote, actualizando el snapshot sin enviar a impresión (BR-003).

### Alternative Flows
- **AF-1 (Modo Invitado / Sin Firebase):** Si el usuario no ha iniciado sesión en Firebase, el snapshot no está disponible y la interfaz muestra una invitación a iniciar sesión para habilitar la auditoría de precios.
- **AF-2 (Sin cambios detectados):** Si todos los precios coinciden con el snapshot, el indicador muestra estado "Al día" (0 pendientes).
- **AF-3 (Error de red con WooCommerce):** Si falla la lectura del catálogo, se muestra mensaje de error respetando el snapshot existente sin alterar datos.

## Business Rules
- **BR-001:** Almacenamiento seguro en Firestore bajo la ruta `users/{uid}/snapshots/{siteId}`.
- **BR-002 (Baseline en Primer Arranque):** Si no existe documento de snapshot previo, se establece el estado actual como punto de partida con 0 pendientes.
- **BR-003 (Criterio de Permanencia):** Un producto con cambio de precio permanece en la lista de pendientes hasta que se imprima su etiqueta o el usuario lo descarte explícitamente.
- **BR-004 (Identificador Inmutable):** La comparación se realiza por `id` numérico de producto de WooCommerce.
- **BR-005 (Productos Variables / Sin Precio):** Se omiten los productos variables sin precio determinable según la regla `isPriceDeterminable` de `FIX-0007`.
- **BR-006 (Paginación Confiable):** La lectura del catálogo utiliza paginación completa guiada por el header `X-WP-TotalPages` (según `FIX-0006`).

## Acceptance Criteria
- **AC-001:** GIVEN un snapshot existente y un catálogo con un producto cuyo `regular_price` cambió WHEN se ejecuta la comparación THEN el producto es detectado con tipo `PRICE_CHANGED` reflejando el precio anterior y el precio nuevo.
- **AC-002:** GIVEN un producto nuevo en catálogo que no existe en el snapshot WHEN se ejecuta la comparación THEN es detectado con tipo `NEW_PRODUCT`.
- **AC-003:** GIVEN una tienda sin snapshot previo (primer uso) WHEN se consulta la auditoría THEN se crea el baseline inicial y se retorna una lista vacía de pendientes (0 cambios).
- **AC-004:** GIVEN productos pendientes WHEN el usuario descarta un producto THEN el snapshot en Firestore se actualiza con su precio actual y el producto desaparece de la lista de pendientes.
- **AC-005:** GIVEN productos agregados a la lista de impresión WHEN se ejecuta la impresión THEN el snapshot de los productos impresos se actualiza en Firestore.
- **AC-006:** GIVEN un usuario no autenticado en Firebase WHEN se consulta la función THEN retorna estado de autenticación requerida sin lanzar excepciones no controladas.
